# Проверка сервисов — 14 ноября 2026

Проверены исходники macOS и Windows, прямые DNS/HTTPS-запросы на Mac и нативные тесты Windows 11 ARM64 в Parallels. Системные DNS, VPN, прокси клиента Telegram и маршруты не переключались. Поэтому результаты ниже относятся к текущему соединению с включённым сторонним VPN и не доказывают доступность через одного только провайдера DNS или через туннель Nimb без этого VPN.

## Нейросети после изменения адресов

Проверялись сайт и API ChatGPT, Claude, Gemini, Grok, ElevenLabs и Perplexity без входа в аккаунты и без API-ключей. Использовался диагностический код приложения; запросы направлялись на адреса, возвращённые DNS выбранного провайдера, с проверкой TLS.

| Вариант | Успешная оценка адресов на Mac | Ограничение |
| --- | --- | --- |
| MagicDNS | 6 из 6 сервисов | Вход в аккаунт и генерация не проверялись |
| malw.link | 6 из 6 сервисов | Вход в аккаунт и генерация не проверялись |
| GeoHide EU | 5 из 6 сервисов | Часть адресов ElevenLabs возвращает региональный отказ |
| GeoHide RU | 5 из 6 сервисов | Часть адресов ElevenLabs возвращает региональный отказ |
| GeoHide US | 5 из 6 сервисов | Часть адресов ElevenLabs возвращает региональный отказ |

Проверка браузера Cloudflare по-прежнему означает только достижимость адреса. Результат без входа в аккаунт не подтверждает работу авторизации, подписки и генерации.

В диагностике исправлены три причины неточных оценок:

- Сайт и API должны каждый отдельно дать не менее 75% успешных ответов. Большой рабочий пул API больше не скрывает полностью недоступный сайт.
- Сбой одного HTTPS-запроса больше не помечает этот IP как неработающий сразу для других доменов. Неудачный запрос повторяется один раз; DNS-проверка также имеет повторную попытку.
- Ошибка 404 страницы сайта не считается успешной проверкой. Ожидаемый ответ API без ключа, например 401, остаётся проверкой достижимости API.

## YouTube, Discord и WARP

На Mac через текущее соединение YouTube вернул 200 для страницы и изображения и 204 для проверочного адреса. Discord вернул 200 для страницы, API Gateway v10 и публичного изображения CDN.

В Windows обычные запросы через системный DNS не прошли: и curl, и HTTP-клиент самого приложения сообщили об ошибке разрешения имён. При этом `Resolve-DnsName` вернул для YouTube адрес `240.0.0.86`, а прямые запросы к проверяемым DNS-провайдерам и HTTPS на полученные от них IP успешно выполнились. Это похоже на влияние DNS-перехвата стороннего VPN через общую сеть Parallels; точная причина без отдельной проверки сетевых настроек не установлена. Настройки гостя и VPN не менялись. Это ограничение текущей проверки Windows, а не подтверждение исправности её туннеля.

В прежней диагностике корневые адреса `i.ytimg.com`, `redirector.googlevideo.com`, `cdn.discordapp.com` и `gateway.discord.gg` могли возвращать 403/404, которые засчитывались как успех. Изображения теперь запрашиваются по реальным публичным путям. Пустой корень видеосервера и обычный HTTP-запрос к WebSocket-шлюзу исключены из проверки: они не подтверждали воспроизведение и сообщения.

Автоматическая оценка теперь называется «адреса доступны». Ответы 4xx/5xx не проходят. Подбор WARP-сервера также отклоняет такие ответы и проверяет служебный адрес Discord вместо одной лишь главной страницы. Формат Gateway сверялся с [документацией Discord](https://docs.discord.com/developers/events/gateway).

Туннель WARP не запускался, а его фактическое рукопожатие и передачу трафика эта проверка не подтверждает. Указанный в настройках порт UDP 500 поддерживается Cloudflare для WireGuard; оснований заменять его без отдельной проверки туннеля нет. См. [документацию Cloudflare](https://developers.cloudflare.com/cloudflare-one/team-and-resources/devices/cloudflare-one-client/deployment/firewall/).

## Telegram

Текущий код macOS успешно установил TLS с проверкой сертификата и получил WebSocket 101 на `149.154.167.220` для четырёх имён:

- `kws2.web.telegram.org`;
- `kws2-1.web.telegram.org`;
- `kws4.web.telegram.org`;
- `kws4-1.web.telegram.org`.

Адреса не менялись. Прокси в клиенте Telegram не перенастраивался; переписка, фото, видео и звонки не проверялись. В [исходном TG WS Proxy](https://github.com/Flowseal/tg-ws-proxy) отдельно описаны случаи проблем с медиа; при наличии такого симптома нужна проверка конкретного клиента, а не замена адресов наугад.

## Самостоятельная проверка после пересборки

1. Когда сторонний VPN можно будет отключить без потери текущего сеанса, выключить остальные туннели и проверить только DNS. Начать с обновлённого MagicDNS, затем сравнить malw.link. Открыть нужные нейросети и выполнить по одному запросу.
2. Отдельно включить YouTube/Discord: проверить воспроизведение и перемотку видео, загрузку вложений и голосовую связь Discord. HTTP-диагностика не заменяет эти действия.
3. Отдельно проверить Telegram с прокси приложения: загрузку сообщений, фото и видео. В клиенте должен быть выбран именно этот локальный прокси.
4. Проверить совместную работу трёх сервисов и последующее выключение DNS с возвратом прежних настроек.

Изменения находятся в исходниках. Установленные приложения и текущие сетевые настройки этой работой не заменялись.
