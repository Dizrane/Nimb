# Ретранслятор отчётов Nimb

Маленький Cloudflare Worker (бесплатный тариф). Приложение отправляет ему отчёт о проблеме, он пересылает его
в ваш Telegram файлом `nimb-report-<номер>.txt` и 90 дней хранит у себя, чтобы их можно было забрать все сразу одним файлом. Токен бота и ваш чат хранятся только в секретах Worker, в приложении их нет.

## Что нужно один раз

1. Бесплатный аккаунт на [cloudflare.com](https://dash.cloudflare.com/sign-up).
2. Бот в Telegram: откройте @BotFather, команда `/newbot`, сохраните токен.
3. Node.js (<https://nodejs.org>).

## Запуск

```
./deploy.sh
```

Скрипт войдёт в Cloudflare, спросит токен бота, найдёт ваш чат, опубликует Worker, положит токен и чат в секреты и
отправит проверочный отчёт. В конце напечатает адрес вида `https://nimb-report.<имя>.workers.dev/`:
его нужно вписать в `Sources/Nimb/Report/ReportSender.swift` (`ReportConfig.endpoint`).
`wrangler.toml` скрипт собирает сам из `wrangler.template.toml` (там id вашего хранилища отчётов), в репозиторий он не попадает.

## Забрать все отчёты одним файлом

Запустите `./export.sh`: скрипт спросит ключ выгрузки (его `deploy.sh` показывает один раз в конце; ключ можно положить в `NIMB_EXPORT_KEY`) и
сохранит `nimb-reports-<дата>.txt` в текущей папке: список всех отчётов сверху и полный текст каждого ниже, старые выше. Этот файл можно передать на
разбор. `./export.sh --clear` после выгрузки удалит выгруженные отчёты (чтобы в следующий раз скачать только новые). Ключ уходит в заголовке
`Authorization: Bearer …`, а не в адресе: адрес остаётся в истории браузера и в журналах. Ключ секретный; сменить его можно командой
`npx wrangler secret put EXPORT_KEY`.

## Автоматические отчёты

Отчёт с `"auto": true` (переключатель «Помогать тестированию» в приложении) приходит в тот же чат и тем же файлом, что и ручной,
но с пометкой `🤖 авто · …` и тегами для поиска в Telegram (`#авто #причина #macos #v0_9_14 #номер_установки`); отчёты, которые
человек написал сам, помечены `✍️`. Все отчёты хранятся 90 дней и выгружаются одним файлом (в выгрузке авто-отчёты помечены
`авто <причина> · установка <номер>`). Чтобы это заработало после обновления кода, нужно один раз снова выполнить `./deploy.sh`
(опубликовать Worker).

## Подпись отчётов Mac

Отчёты Mac подписаны ключом, который есть только у официальных сборок: приложение считает HMAC-SHA256 от строки
`nimb1|номер|версия|платформа|установка|sha256(текст)`, и Worker сверяет подпись раньше всего остального. Отчёт без верной подписи
отклоняется с кодом 403: он не попадает ни в Telegram, ни в хранилище, ни в счётчик адреса. Сборка из исходников ключа не имеет, поэтому
её отчёты не принимаются, даже если в её коде убрать проверку.

- Главный ключ: `openssl rand -hex 32 > ~/.config/nimb/report.key` (`chmod 600`), в репозитории его нет, в приложение он не попадает.
  `./deploy.sh` кладёт его в секрет `REPORT_KEY`.
- У каждой версии свой ключ: HMAC-SHA256 от `nimb-key|версия` под главным ключом (`scripts/report_key.py`). `scripts/build_app.sh` вшивает в сборку
  только ключ её версии, а Worker получает такой же из версии, которая указана в отчёте. Поэтому ключ, вытащенный из релиза, подписывает отчёты
  только этой версии, а когда выходит следующая, Worker отклоняет её как не последнюю. Ничего делать при выпуске не нужно: Worker заново
  выкладывать не надо.
- Сменить главный ключ (нужно, только если утёк он сам, например с этого Mac): создать новый файл, выпустить версию с ним, в секрет
  `REPORT_KEY` положить новый, а старый — в `REPORT_KEY_PREV`, чтобы отчёты ещё не обновившихся продолжали приниматься. Когда все обновятся,
  секрет `REPORT_KEY_PREV` удалить.
- Версии Mac до подписи (0.9.22 и старше) принимаются без подписи, пока их ждут. Когда все тестеры обновятся, задайте переменную
  `UNSIGNED_UP_TO=0.0.0` (в `wrangler.template.toml`, раздел `[vars]`; `wrangler.toml` из него собирается заново) и повторите `./deploy.sh`: бесподписные отчёты Mac перестанут приниматься.
- Сборка для Windows пока ничего не подписывает, её отчёты принимаются как раньше.
- Отчёты Mac принимаются только из последней версии: Worker спрашивает у GitHub последний релиз (раз в 10 минут на узел Cloudflare, остальное
  из кеша) и отвечает 403 `outdated` с номером последней версии на отчёты от более старых. Если GitHub не ответил или вернул не обычный
  тег `vX.Y.Z`, ограничения нет (отчёт лучше принять, чем потерять из-за сбоя проверки). Переменная `LATEST_MAC` задаёт версию вручную,
  `LATEST_MAC=off` отключает проверку. Версия, которая новее последней (сборка до выпуска), принимается.
- Если секрета `REPORT_KEY` нет, подписанные отчёты не принимаются совсем (лучше видимая ошибка, чем открытая дверь).

## Что защищает от мусора

- подпись отчёта Mac (выше);
- принимает только JSON нужной формы, не больше 100 КБ;
- не больше 5 отчётов в минуту с одного адреса (Cloudflare Rate Limiting);
- адреса отправителя не пересылаются и не сохраняются.

