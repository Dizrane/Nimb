# Nimb для Windows: черновик плана

Статус: **только бумага**, кода нет. Версия macOS-приложения, с которой снят план: 0.9.6. Проверка фактов в сети: 2026-10-21.
Пометки: **[ок]** подтверждено в документации или репозитории (ссылки в конце), **[?]** не подтверждено, проверить до того, как на это опираться.

Принципы те же, что у macOS-версии: всё бесплатное (ни платных сертификатов, ни платных серверов), в репозитории нет личных данных, лицензия проекта PolyForm Noncommercial.

## 1. Что должно уметь приложение

Те же три сервиса, что на macOS, плюс обвязка. Источник правды по поведению — исходники macOS-версии.

| Функция | Что делает на Windows | Откуда брать поведение |
|---|---|---|
| Smart DNS для нейросетей | Ставит DNS одного из четырёх провайдеров на все рабочие сетевые адаптеры, при выключении возвращает прежние (DHCP или свои). Сброс кэша DNS. Проверка, какой провайдер сейчас работает с ChatGPT, Claude, Gemini, Grok, ElevenLabs, системный DNS при проверке не трогается. | `Sources/Nimb/Services.swift` (провайдеры и адреса), `DNSManager.swift`, `ServiceProbe.swift`, `SiteChecker.swift` |
| Прокси для Telegram | Локальный MTProto-прокси на `127.0.0.1` (порт 1443 или следующий свободный из 20), ключ 16 байт, ссылка `tg://proxy?server=127.0.0.1&port=…&secret=dd…`. Внутри: WebSocket к шлюзу `kws<N>.web.telegram.org`, запасной путь прямым TCP. Автозапуск, если был включён. | `Sources/Nimb/TelegramProxy/` (порт TG WS Proxy от Flowseal, MIT; у оригинала есть и сборки для Windows) |
| Туннель WARP (YouTube, Discord) | Личная анонимная учётная запись Cloudflare WARP на каждую установку, AmneziaWG до Cloudflare, полный туннель (маршруты `/1`), ждёт рукопожатие до 16 с и при неудаче всё откатывает. При удалении или смене аккаунта запись у Cloudflare удаляется. | `Sources/Nimb/Warp/`, `Resources/nimb-tunnel.sh`, `Resources/warp-preset.conf` |
| Отчёт о проблеме | Кнопка в настройках: собирает журнал и диагностику, убирает личное, шлёт JSON `{"v":1,"id","app","platform":"windows","text"}` на ретранслятор из `report-relay/` (он уже принимает `windows`). Не вышло — отчёт копируется, можно написать разработчику в Telegram. | `Sources/Nimb/Report/` (лимиты: тело до 100 КБ, у приложения обрезка до 60 000 знаков; 5 отчётов в минуту) |
| Обновления | Проверка релизов GitHub раз в 10 минут, пока Nimb запущен (окно открыто или нет); одно уведомление на версию; переключатель в настройках и в первой настройке. | `Updater.swift`, `UpdateSchedule.swift`, `Notifier.swift` |
| Удаление без следов | Возвращает DNS, гасит туннель и снимает маршруты, удаляет запись WARP, службу, драйвер-адаптер, файлы, автозапуск, журнал, правила брандмауэра. Проверка «ничего не осталось». | `Uninstaller.swift`, `scripts/check_removed.sh` |
| Остальное | Первая настройка по шагам, главная с одним выключателем «всё сразу» и тремя отдельными, значок в области уведомлений (аналог меню в строке меню), автозапуск, один экземпляр, список «Что открывает туннель», доступность для экранного диктора. | `Onboarding*.swift`, `StatusMenuController.swift`, `SingleInstance.swift`, `LaunchAtLogin.swift` |

Не переносится: `MoveToApplications`, `FloatAboveMainWindow`, sudoers, App Translocation (у каждого есть свой аналог в п. 4–5 или он не нужен).

## 2. Что взять из репозитория

- **Графика** `art-studio/deliver/` (6,6 МБ, всё нарисовано заново, лицензия в `CREDITS.md`): PNG-кадры (`icon-*`, `halo`, `hood`, `paper-plane`), готовые JS-анимации на canvas (`header/header-motion.js`, `media-motion/media-motion.js`, `icon-welcome`, `paper-plane/wander.js`), макет окна `desktop-layout/reference.html`, значки `app-icon/*.png` (из PNG 1024 делается `.ico`). Это главный довод за веб-интерфейс: всё это уже HTML/JS.
- **Мир на глобусе**: `Resources/world.json`, `scripts/make_world.py`.
- **Тексты** (русские): README, строки в `Onboarding*.swift`, `SettingsView.swift`, `*Page.swift`, ошибки в `Warp/*`, `Report/*`. Вынести в один `windows/frontend/src/strings.ru.json`; слова про Mac (Корзина, Finder, пароль администратора, строка меню) заменить на Windows-аналоги (корзина, Проводник, подтверждение UAC, значок у часов).
- **Список сайтов туннеля**: массив `sites` в `Sources/Nimb/TunnelSitesWindow.swift` (28 сайтов: имя + тип, по убыванию популярности) плюс фраза «Туннель не поможет там, где сервис сам закрыт для российских IP-адресов». Скопировать в JSON; позже можно сделать общий `shared/tunnel-sites.json`, macOS пока не трогать.
- **Правила разбора настроек** `Sources/Nimb/Warp/WarpConfig.swift` перенести в Go один в один, тесты из `Tests/NimbTests` перенести как таблицу случаев:
  - разделы только `[Interface]` и `[Peer]`; пир ровно один;
  - берутся только известные ключи; всё остальное попадает в «пропущено» с причиной; `DNS`, `ListenPort`, `Table`, `SaveConfig` пропускаются, `PreUp/PostUp/PreDown/PostDown` **никогда не выполняются**;
  - `PrivateKey`, `PublicKey`, `PresharedKey` — base64 ровно на 32 байта;
  - `Address` и `AllowedIPs` — CIDR по регулярке из файла; `MTU` 576–1500; `Endpoint` — `host:port` или `[v6]:port`, порт 1–65535; `PersistentKeepalive`, `ProtocolVersion` — числа;
  - `Jc Jmin Jmax S1–S4 H1–H4` — число или диапазон; остальные ключи AmneziaWG (`I1–I5`, `HeaderProtectionKey`, `ContentPaddingAddition`, `RekeyAfterTime`…) — печатные ASCII, не длиннее 4096, значения `I1–I5` свободной формы (комментарий ` #` в них не вырезается);
  - обязательны PrivateKey, Address, PublicKey, Endpoint, AllowedIPs; без `PersistentKeepalive` добавляется 25;
  - результат — плоские строки `key=value`, их читает служба, ничего из них не исполняется.
- **Регистрация WARP** `Warp/WarpRegistration.swift`: `POST /v0a2223/reg` на `zero-trust-client.cloudflareclient.com` и запасной `api.cloudflareclient.com` (тот же JSON, заголовки `User-Agent: okhttp/3.12.1`, `CF-Client-Version: 1.1.1.1/6.81`), ключ X25519 из `crypto/ecdh`, порт сервера 500, `DELETE /v0a2223/reg/<id>` с Bearer-токеном при удалении. Заготовка `warp-preset.conf` (MTU 1280, Jc 120, Jmin 23, Jmax 911, S1=S2=0, H1–H4 = 1–4, длинный `I1`, `AllowedIPs 0.0.0.0/0, ::/0`, keepalive 25) встраивается через `go:embed`, ключей и личных данных в ней нет.
- **Лицензии**: добавить в `THIRD-PARTY-NOTICES.md` Wails (MIT), wintun (текст его «Prebuilt Binaries License»), библиотеку значка в области уведомлений. Уже есть: TG WS Proxy, amneziawg-go.

## 3. Стек: Go для ядра, Wails для интерфейса

**Рекомендация: Go + Wails v2** (стабильная 2.17.0 от 2026-10-18 [ок]). Wails v3 пока бета (`3.0.0-beta.34`, 2026-10-20 [ок]); в нём есть значок в области уведомлений и несколько окон, но брать бету за основу рано.

Почему Go:
- AmneziaWG на Windows целиком на Go: `amneziawg-go` (MIT) уже содержит `tun/tun_windows.go`, `conn/bind_windows.go` и `ipc/uapi_windows.go` [ок]. Подключается как библиотека без CGO и без чужих процессов; на macOS мы уже собираем тот же демон из Go.
- Одним языком пишутся служба, туннель, DNS, Telegram-прокси, отчёты и обновления. Логика macOS (разбор настроек, регистрация WARP, прокси) переносится почти построчно.
- Собирается с Mac: `GOOS=windows GOARCH=arm64|amd64 CGO_ENABLED=0` [?] (для чистого Go верно, но для Wails из-под macOS не проверял, см. этап 1). Windows понадобится только в виртуальной машине для запуска.
- Один exe в 10–20 МБ, без установки .NET.

Почему Wails, а не C# + WinUI 3:
| | Go + Wails | C# + WinUI 3 |
|---|---|---|
| Анимации и графика Nimb | работают как есть (HTML/JS/PNG) | переписывать в XAML/Composition |
| Туннель AmneziaWG | библиотека Go в том же языке | нет аналога на C#; либо P/Invoke в Go-DLL, либо отдельный процесс |
| Сборка | с Mac, Windows нужен для запуска | нужен Windows с Visual Studio (тяжело в ARM-ВМ) |
| Размер и среда | WebView2 (на Windows 11 есть из коробки [?], на Windows 10 бывает не везде) | .NET и Windows App Runtime |
| Внешний вид | веб (но весь дизайн Nimb и так нарисован сам) | родной Windows |
| Значок у часов | в v2 нет встроенного [ок: запрос в трекере висит без ответа], нужна отдельная библиотека, совместимость с Wails v2 **[?]** | тоже нет встроенного (нужна библиотека) |
| Риск | v2 одно окно (окно «Что открывает туннель» станет страницей внутри) | зрелый, но больше работы |

Что есть в Wails v2 для нас [ок]: `HideWindowOnClose`, `StartHidden`, `SingleInstanceLock`, `Theme`, Windows 10/11 на amd64 и arm64, установщик `wails build -nsis`.

Раскладка (предложение):
```
windows/
  SPEC.md
  go.mod                      модуль github.com/Dizrane/Nimb/windows
  cmd/nimb/                   интерфейс (Wails), значок у часов, Telegram-прокси, отчёты, проверка обновлений. Права обычного пользователя.
  cmd/nimb-svc/               служба NimbHelper: DNS, туннель, установка обновления, уборка. LocalSystem.
  internal/{warp,dnsx,tgproxy,report,update,ipc,config}/
  frontend/                   веб-часть: страницы, strings.ru.json, ассеты из art-studio/deliver
  installer/                  NSIS-скрипт, проверка «ничего не осталось» (PowerShell)
```
Telegram-прокси живёт в процессе интерфейса: он слушает только `127.0.0.1`, прав не требует.

## 4. Права администратора, DNS, туннель

### Права без запроса UAC при каждом переключении
Аналог правила sudoers: **маленькая служба Windows**, которая ставится один раз.
- Установщик работает с правами администратора (один запрос UAC при установке), кладёт `nimb-svc.exe` в `C:\Program Files\Nimb\`, регистрирует службу `NimbHelper` (автозапуск, учётная запись LocalSystem). Больше UAC не нужен, пока пользователь не удаляет Nimb.
- Интерфейс (`nimb.exe`, манифест `asInvoker`) говорит со службой по **именованному каналу** `\\.\pipe\nimb-helper`: запретить сетевых клиентов (`PIPE_REJECT_REMOTE_CLIENTS`), доступ только у SYSTEM, администраторов и интерактивного пользователя (SID пользователя, который ставил Nimb, или группа Users **[?]** решить на этапе 2).
- Протокол **закрытый**, как строки в sudoers: `dns.set{providerId}`, `dns.restore`, `tunnel.up`, `tunnel.down`, `tunnel.status`, `tunnel.register`, `tunnel.unregister`, `update.apply`, `uninstall.prepare`. Никаких путей и команд от клиента: адреса провайдеров и пути лежат в самой службе; настройки туннеля, присланные интерфейсом, проходят те же проверки, что в п. 2, и записываются в `C:\ProgramData\Nimb\warp.conf` (права только SYSTEM и администраторы).
- Модель угроз та же, что у `NOPASSWD` в sudoers: любая программа от имени этого пользователя может включить или выключить DNS и туннель, но не выполнить свой код с правами SYSTEM. Это нужно сказать в README честно.
- Образец устройства: официальный клиент AmneziaWG для Windows работает так же (служба менеджера и служба туннеля от LocalSystem, интерфейс получает права от службы) [ок, `docs/attacksurface.md`].

### Смена DNS и возврат
- Какие адаптеры: все рабочие (Up) физические, Wi-Fi и Ethernet, без адаптера Nimb и без виртуальных (Hyper-V, WSL, VPN). Служба слушает смену сети (появился новый адаптер, ушёл Wi-Fi) и применяет настройку к новым.
- Перед изменением служба **записывает прежнее состояние** каждого адаптера в `C:\ProgramData\Nimb\dns-backup.json` (DHCP или статический список, IPv4 и IPv6). Возврат: DHCP → `netsh interface ip set dnsservers name=<индекс> dhcp` (то же для `ipv6`); статический список → вернуть его. Восстановление срабатывает и при запуске службы (если пользователь выключил Smart DNS, а служба была убита), и в деинсталляторе.
- Способ: на первом этапе **netsh** (работает на любой Windows, легко отлаживать), с индексом адаптера, а не именем (имена бывают русскими). Вывод netsh зависит от языка, поэтому читать состояние не из него, а из реестра `HKLM\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters\Interfaces\{GUID}` (пустой `NameServer` = DHCP) **[?: проверить в ВМ]**, либо через `GetInterfaceDnsSettings`. Позже можно перейти на вызов `SetInterfaceDnsSettings` из `iphlpapi` (есть с Windows 10 build 19041, версия 2004 [ок]) без процессов-обёрток. PowerShell (`Set-DnsClientServerAddress`, `-ResetServerAddresses`) запускается около секунды и тянет за собой профиль, поэтому как основной не берём.
- После смены: `ipconfig /flushdns` (или `DnsFlushResolverCache`).
- Подводные камни, которых нет на Mac: (1) если роутер раздаёт IPv6-адреса DNS (RDNSS/DHCPv6), Windows может спрашивать их мимо Smart DNS, значит IPv6-DNS на адаптере надо тоже переопределить **[?]**; (2) «Smart Multi-Homed Name Resolution» шлёт запросы на все адаптеры сразу, поэтому после включения туннеля проверить, что запросы идут туда, куда ожидается; (3) DNS через HTTPS в браузерах и на Windows 11 обходит системный DNS, как и на Mac, в проверку сервисов это уже заложено.

### Подъём туннеля через amneziawg-go и wintun
- Ядро: `github.com/amnezia-vpn/amneziawg-go/v3` (последний тег `v3.1.20260828` [ок]; на macOS закреплён коммит `b5928ef…`, версию для Windows закрепить так же). В службе: `tun.CreateTUN("Nimb", 1280)` → `device.NewDevice` → `IpcSet` теми же строками `key=value`, которые на macOS собирает `nimb-tunnel.sh` (это формат UAPI, ключи `jc, jmin, … i1…i5` уже совпадают) → назначение адреса и маршрутов.
- **wintun.dll** (0.14.1, сборки amd64, arm64, x86, arm [ок]) кладётся рядом со службой. Драйвер ставится самим `wintun.dll` при создании адаптера, права администратора нужны **[?: в README не сказано, по опыту нужны; служба и так SYSTEM]**. Лицензия бинарников разрешает распространять `wintun.dll` вместе с программой, которая пользуется им только через `wintun.h` [ок]; менять DLL нельзя.
- Маршруты: как на macOS, `0.0.0.0/1`, `128.0.0.0/1`, `::/1`, `8000::/1`, **не** `/0`. Причина: официальный клиент для `AllowedIPs` с `/0` включает «аварийный выключатель» (правила брандмауэра, блокирующие всё, кроме туннеля и DNS на заданные серверы), а с `/1` не включает [ок, `docs/netquirk.md`]. Нам нужно поведение, как у Mac: не получилось поднять туннель — интернет остаётся.
- Пакеты туннеля не должны идти в сам туннель. На macOS это делали хост-маршрут и «сторож» (`watch_network`). На Windows у `amneziawg-go` есть `conn/bind_windows.go` и `BindSocketToInterface`, а в `amneziawg-windows` — `interfacewatcher.go`, который перепривязывает сокет при смене сети [ок, что файлы есть]. Годятся ли они для импорта в нашу службу или их нужно скопировать (MIT) — **[?]**: корень `amneziawg-windows` это `package main`; решить на этапе 3 после чтения кода.
- Вариант Б (запасной): использовать готовую встраиваемую DLL `amneziawg-windows` (`tunnel.dll`, экспорт `WireGuardTunnelService(conf, name)`, собирается `build.cmd`, нужен CGO) [ок]. Недостаток: служба на туннель, «аварийный выключатель» для `/0`, сложнее чисто удалить.
- Вариант В (для самой первой проверки): поставить готовый клиент AmneziaWG для Windows (MIT, релиз `3.1.0` от 2026-08-21, MSI для amd64, arm64, x86 [ок]), импортировать туда конфигурацию с нашей заготовкой. Командная строка клиента: `/installtunnelservice <файл.conf>`, `/uninstalltunnelservice <имя>` [ок]. Разбор настроек в клиенте знает `I1…I5` и `HeaderProtectionKey` [ок], значит заготовка должна быть принята.
- Рукопожатие: ждать до 16 с (опрос `last_handshake_time_sec`), без него — полный откат. Состояние (`pid`, адаптер, маршруты) в `C:\ProgramData\Nimb\tunnel.state`; при старте службы, если туннеля нет, убрать оставшиеся маршруты и адаптер (аналог «уборки при запуске» из 0.9.5).
- WARP на Windows: сам API регистрации не привязан к ОС (обычный HTTPS), поэтому код 1:1 из macOS-версии **[?: на Windows не пробовал]**. Cloudflare и на Windows предлагает официальный клиент WARP [ок]; сторонний `wgcf` создаёт такие же профили, порт по умолчанию там 2408 [ок]; у нас в заготовке 500. Условия бесплатного использования WARP и блокировки сети конкретными провайдерами в РФ **[?: не подтверждено, не искал глубже]**.

## 5. Установщик и обновления

- **Установщик**: NSIS (`wails build -nsis` [ок], на Mac ставится `brew install nsis`), один `Nimb-Setup-<версия>-<arch>.exe`. На каждую архитектуру отдельный (amd64 — основной, arm64 — для ARM-ноутбуков и тестов). Ставит в `C:\Program Files\Nimb`, регистрирует службу, запись «Установка и удаление программ», ярлык в Пуске, автозапуск `HKCU\…\Run` по выбору. Альтернатива: Inno Setup (бесплатный, но сборка только на Windows).
- **Удаление**: деинсталлятор вызывает `uninstall.prepare` (DNS назад, туннель вниз, запись WARP удалена у Cloudflare, адаптер wintun удалён), останавливает и удаляет службу, затем убирает `Program Files\Nimb`, `ProgramData\Nimb`, `%LOCALAPPDATA%\Nimb`, `%APPDATA%\Nimb`, ключи реестра, автозапуск, ярлыки и правила брандмауэра. Скрипт-проверка (PowerShell, аналог `scripts/check_removed.sh`) до/после, на ВМ.
- **Обновления**: интерфейс спрашивает `api.github.com/repos/Dizrane/Nimb/releases/latest`, если лимит (403/429) — страницу последнего релиза, как на macOS. Есть ли для Windows отдельный тег или общий релиз с двумя наборами файлов, решить заранее: проще один релиз с файлами обеих систем и `SHA256.txt`, в имени файла `windows`.
- Установка обновления: скачать установщик в `ProgramData\Nimb\updates`, служба сама повторно запрашивает контрольную сумму у GitHub (а не доверяет интерфейсу) и запускает установщик тихо (`/S`) от SYSTEM, значит UAC не нужен. Так как Authenticode-подписи не будет, добавить **собственную подпись ed25519**: открытый ключ вшит в программу и службу, подпись лежит в релизе (по образцу `signify` у официального клиента WireGuard [ок]). Ключ подписи хранить вне репозитория.

## Результат Smart DNS в службе (2026-10-21, `internal/dnsx`, `internal/helper/dns_windows.go`)

Команды `dns.set` (только ID провайдера из списка службы, никаких адресов от окна) и `dns.restore`. Список провайдеров сверяется с `Services.swift` тестом. Проверено в Windows 11 ARM64, от имени обычного пользователя, без UAC.

- **Какие адаптеры:** подключённые Ethernet и Wi-Fi, у которых стоит признак «железный» (`HardwareInterface`). Туннель Nimb, чужие VPN, виртуальные коммутаторы Hyper-V, WSL и виртуалок не трогаются. Исключение, о котором надо помнить: если Wi-Fi или сетевая карта привязана к внешнему виртуальному коммутатору Hyper-V, рабочим становится его виртуальный адаптер и Smart DNS его не увидит **[?]**.
- **Чтение и запись:** статический `NameServer` читается из реестра (`...\Tcpip\Parameters\Interfaces\{GUID}`, пусто означает DHCP, не зависит от языка Windows), пишется `SetInterfaceDnsSettings` только с флагом имён серверов (список поиска и остальное не трогаются). Пустое значение возвращает DHCP **[ок]**.
- **[ок] Резервная копия** `dns-backup.json` пишется до изменения адаптеров и хранит первое состояние каждого адаптера, сколько бы раз ни меняли провайдера. Свой статический DNS пользователя (9.9.9.9) возвращается, DHCP остаётся DHCP.
- **[ок] Чужая правка:** если после включения человек сам поменял DNS адаптера, выключение Smart DNS его не трогает (в журнале пометка).
- **[ок] Убитая служба** при включённом Smart DNS: DNS остаётся на провайдере, служба поднимается сама, копия на диске цела, `dns.restore` потом всё возвращает.
- **[ок] Вместе с туннелем:** DNS адаптера туннеля сразу меняется на адреса провайдера (иначе имена спрашивались бы у 1.1.1.1 и Smart DNS молчал бы) и возвращается на 1.1.1.1 при выключении; при новом подъёме туннеля берутся адреса провайдера.
- **[ок]** Системный резолвер для `chatgpt.com` отвечает адресами провайдера, а `8.8.8.8` настоящими. Неизвестный ID, IP-адрес, другой регистр, пустая строка отвергаются.
- **[?]** Не проверено: новый адаптер во время работы (наблюдатель написан, в виртуалке не проверялся), IPv6-DNS от роутера (в ВМ его нет; Windows может спрашивать такие серверы мимо Smart DNS), DNS-over-HTTPS Windows 11, клиентская политика предприятия.

## Результат проверки провайдеров и разбор отчёта тестера (2026-10-21, `internal/probe`, `internal/browserdns`, `internal/dnsx`)

Жалоба: «ChatGPT открывается, но не отвечает» (GeoHide US, Windows 11 25H2, одно подключение Wi-Fi). В отчёте не было ни проверки провайдеров, ни IPv6-серверов DNS, ни списка подключений: причину по нему доказать нельзя. Проверены четыре гипотезы.

- **[ок] Проверка провайдеров** (паритет с Mac): пакет `internal/probe` — порт `ServiceProbe.swift` (цели, слова и фразы отказа, `classify`, пороги 0.75 и 0.1; тесты читают Swift-файл и сверяют списки). DNS-запрос к серверу провайдера напрямую (UDP 53, без смены DNS системы и без прав администратора), потом HTTPS к каждому адресу с подменой адреса (SNI и Host настоящие, редиректы не идут, до 30 КБ тела, соединение 3 с, запрос 6 с, 24 запроса сразу). В окне: кнопка «Проверить сервисы» с прогрессом «Проверено N из M», у каждого провайдера значок скорости и плашки сервисов, ⓘ с подробностями, плашка «Рекомендуем» и «Выбрать»; первая настройка: «Подобрать и включить». Проверено в Windows 11 ARM64 на живых провайдерах (13 с): рекомендует GeoHide (EU); в окне прошли кнопка, прогресс, результаты и шаг первой настройки (после него DNS на адаптере стал `143.20.64.192,45.13.237.213`).
- **[подтверждено, вероятная причина] Мёртвые адреса пула.** У GeoHide (US) из четырёх адресов пула два не отвечают (`107.175.76.134`, `192.3.233.253`: соединение на 443 не устанавливается), у GeoHide (RU) три из четырёх (`159.194.200.33`, `193.233.112.67`, `193.233.112.88`); у EU и Comss все живые. Проверка выдаёт у US и RU «работает 0 из 5». Браузер, получивший такой адрес первым, ждёт тайм-аут, а долгие запросы чата (потоки) рвутся: страница открывается с живого адреса, чат нет. Это видно с компьютера в России (адреса одни и те же с Mac и из виртуалки); на сети тестера могло быть иначе. Тестер переключал провайдеров вслепую, теперь есть проверка и «Рекомендуем».
- **[не подтверждено] Другие имена.** Все имена ChatGPT (`chatgpt.com`, `chat.openai.com`, `api.`, `auth.`, `auth0.`, `platform.openai.com`, `cdn.oaistatic.com`, `persistent.oaistatic.com`, `files.oaiusercontent.com`, `ab.chatgpt.com`, `ws.chatgpt.com`, `webrtc.chatgpt.com`, `cdn.openai.com`) все четыре провайдера отдают своим пулом; не перехватываются только `events.statsigapi.net`, `featureassets.org`, `challenges.cloudflare.com` (Comss перехватывает статистику и Sentry, на чат это не влияет). Добавлять цели в список не нужно.
- **[подтверждено механизм, на сети тестера не проверено] IPv6-серверы DNS.** Windows спрашивает IPv6-серверы адаптера раньше IPv4. В виртуалке: IPv4 = GeoHide, IPv6 = «роутер» (свой сервер) — все имена приходят от «роутера», то есть настоящими; сервер IPv6, который молчит, даёт задержку около секунды на первое имя. Окно ставило только IPv4, поэтому на сети, где роутер раздаёт DNS по IPv6, Smart DNS не действовал бы (ChatGPT открывался бы напрямую и не отвечал бы). Исправлено: если у адаптера есть серверы IPv6 (заданные вручную или от сети), служба кладёт туда адреса провайдера в виде `::ffff:IPv4` (Windows их не использует, имена приходят с IPv4-серверов провайдера, серверы роутера не спрашиваются), в копию (`dns-backup.json`) идёт прежнее значение, при выключении, в уборке и при удалении оно возвращается; если IPv6-серверы человек поменял сам, они остаются его. Проверено в виртуалке: включение, смена провайдера, выключение, возврат. **Не проверено:** сервер IPv6 именно от роутера (RDNSS): в виртуалке такого нет; расчёт на то, что заданный вручную список IPv6 важнее выданного сетью.
- **[нет действия] Другие подключения.** Windows может спрашивать DNS и у других подключений (VPN, виртуальные коммутаторы); Nimb меняет только Wi-Fi и Ethernet устройства компьютера. Проверить не на чем (в виртуалке одно подключение), поэтому в отчёт добавлен список всех подключений с их DNS, а не поведение.
- **[ок] Firefox.** Если Firefox установлен и «DNS через HTTPS» в нём не выключен (`network.trr.mode` 0 или 5 в `prefs.js`/`user.js`), при включённом Smart DNS на странице «Нейросети» показывается подсказка (как на Mac). Chrome и Edge не смотрятся (по умолчанию они берут DNS системы).
- **[ок] Отчёт.** Добавлены разделы «Подключения и их DNS» (все подключения, IPv4 и IPv6, вручную или от сети), «Проверка DNS» (по провайдерам: сколько работает, счёт по сервисам, медиана, отказы и адреса без нормального ответа) и строка про Firefox. Если проверки в последние 10 минут не было, она запускается при сборе отчёта (форма ждёт на 10–20 секунд дольше). Имена подключений, которые Windows дала сама («Wi-Fi», «Ethernet», «Беспроводная сеть» и т. п.), остаются, остальные заменяются на «‹подключение N›», как на Mac; адреса пулов провайдеров остаются (они ничьи), остальные адреса скрыты как раньше. В службе строка «DNS на …» теперь показывает и IPv6.
- Установщик пересобран; снимок «до» и «после» на Windows 11 ARM64 (установка, Smart DNS, окно, удаление): `CLEAN`.
